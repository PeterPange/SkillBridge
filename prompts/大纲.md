# SkillBridge AI——企业员工智能培训与能力发展 Agent 平台

项目面向企业 HR 培训场景，通过员工画像、岗位能力模型、课程资源、企业知识库和 AI Agent，实现**能力差距分析 → 个性化课程推荐 → 学习路径规划 → 培训问答 → 学习反馈 → 动态调整**的完整闭环。这个方向与培养方案中的 HR 知识图谱、个性化培训推荐、自适应学习路径、互动式培训和 HR 系统集成是一致的。

整个项目可以拆成下面 **12 个部分**。

---

## 一、业务调研与需求分析

### 要解决什么

先确定真实业务问题，而不是先做 Agent。

我们选择一个具体场景：

> 软件企业计划把部分 Java / 后端开发人员培养成 AI Engineer，但 HR 不清楚每个员工缺什么能力、应该学习什么课程，以及怎样制定个性化培训计划。

### 这一部分包含

```text
企业培训现状调研
        ↓
岗位体系调研
        ↓
员工能力体系调研
        ↓
课程体系调研
        ↓
现有培训流程分析
        ↓
业务痛点分析
        ↓
系统需求确定
```

主要研究几个问题：

```text
员工目前具备什么能力？

AI Engineer 要求什么能力？

两者之间差多少？

有什么课程能够弥补这些能力？

课程应该以什么顺序学习？

培训以后员工能力有没有提升？
```

### 最终产出

```text
业务流程图
用户角色定义
核心业务场景
系统需求说明
MVP范围
```

你培养方案前期要求调研 HR 培训系统架构、岗位能力模型、课程体系和数据来源，本质上就是这个阶段。

# 三、统一技能体系与数据标准化

这是一个非常重要、也很适合面试讲的技术模块。

因为不同平台的技能名称不统一。

例如：

```text
Generative AI

GenAI

Generative Artificial Intelligence

Large Language Model Applications
```

本质可能属于同一个或高度关联的 Skill。

因此需要建立：

# Skill Normalization

整体流程：

```text
外部Skill
    ↓
文本标准化
    ↓
Alias匹配
    ↓
Embedding相似度
    ↓
候选标准Skill
    ↓
LLM语义校验
    ↓
统一Skill ID
```

最终所有系统数据统一成：

```text
skill_id = SKILL_001

name = Generative AI
```

这样：

```text
岗位
员工
课程
培训记录
```

才能使用统一技能体系。

# 五、员工能力画像

Knowledge Graph 是公共知识。

Employee Profile 是个人状态。

系统为每个员工建立：

```text
基本信息
当前岗位
目标岗位
技能列表
技能等级
学习历史
考试成绩
项目经历
课程完成情况
学习偏好
```

例如：

```text
李明

Java             4
Python           2
ML               1
GenAI            0
AI Agent         0
Docker           2
```

但技能等级不能只是一个数字。

还可以保存 Evidence：

```text
Python = Level 2

证据：

技能考试：65
项目经历：有Python项目
员工自评：2
培训记录：Python基础已完成
```

这样以后系统可以解释：

> 为什么认为你 Python 是 Level 2？

# 六、岗位能力差距分析 Skill Gap

这是整个推荐系统的入口。

例如：

目标岗位 AI Engineer：

```text
Python             3
Machine Learning   2
Generative AI      3
AI Agent           3
Deployment         2
Monitoring         2
```

李明：

```text
Python             2
Machine Learning   1
Generative AI      0
AI Agent           0
Deployment         1
Monitoring         1
```

程序计算：

```text
Skill Gap

Python             +1
Machine Learning   +1
Generative AI      +3
AI Agent           +3
Deployment         +1
Monitoring         +1
```

这一部分**不用 LLM 算**。

传统算法负责。

最后得到：

```text
员工 → 缺失技能 → 缺失程度
```

这成为课程推荐模块的输入。

# 七、个性化课程推荐系统

培养方案明确要求根据员工画像和培训需求进行个性化推荐。

推荐分两步。

### Candidate Generation

根据：

```text
Skill Gap
```

找到：

```text
Course -TEACHES→ Skill
```

例如：

```text
缺少 AI Agent

↓

Develop AI Agents
```

---

### Course Ranking

候选课程再打分：

```text
Skill Gap覆盖程度
+
技能重要性
+
课程难度匹配
+
员工基础
+
课程前置条件
+
学习时间
+
历史学习偏好
```

例如：

```text
Course A   0.91
Course B   0.82
Course C   0.76
```

输出 Top-K。

系统因此不是：

> LLM，你觉得我应该学什么？

而是：

```text
真实 Skill Gap
        ↓
候选课程生成
        ↓
推荐模型排序
        ↓
LLM解释为什么推荐
```

# 九、企业知识库 RAG

前面的模块解决的是：

> 学什么。

RAG 解决：

> 为什么、怎么学、公司规定是什么。

知识库可以放：

```text
企业员工培训制度
岗位说明书
课程材料
技术培训文档
员工手册
晋升制度
AI Engineer岗位说明
课程Learning Objectives
```

流程：

```text
PDF / Word / Web
        ↓
文档解析
        ↓
标题级分块
        ↓
Embedding
        ↓
pgvector
        ↓
Retriever
        ↓
Reranker
        ↓
LLM
```

例如员工问：

> 为什么给我推荐 AI Agent？

系统检索：

```text
目标岗位能力要求

+

AI Agent课程学习目标
```

然后回答：

```text
你的目标岗位 AI Engineer
需要 Agent Development 能力，

当前技能等级为 0，
目标等级为 3，

推荐课程覆盖 Agent 构建、
Tool Calling 和 Agent workflow，
因此被排入你的学习路径。
```

# 十一、学习反馈与动态调整

这是系统形成闭环的关键。

员工完成课程以后：

```text
Course completed

考试：85分
```

写入：

```text
training_record
assessment
```

然后更新 Skill Evidence：

```text
Generative AI

0 → 1
```

系统重新计算：

```text
Employee Skill
       ↓
Skill Gap
       ↓
Course Recommendation
       ↓
Learning Path
```

于是：

```text
第一次：

A → B → C → D

学完A/B后：

C → D
```

如果考试成绩不好：

```text
追加基础课程
```

如果员工进度很快：

```text
跳过部分基础课程
```

这才是真正的：

> **Adaptive Learning。**

# 整个项目最终的数据闭环

把前面的所有部分连起来，其实就是这一条：

```text
        真实职业数据
        ESCO / O*NET
              │
              ↓
          岗位能力模型
              │
              │

              │
              ↓
         课程匹配推荐
              │
              ↓
        Learning Path
              │
              ↓
           员工学习
              │
              ↓
        考试 / 学习反馈
              │
              ↓
         更新员工画像
              │
              ↓
        重新计算Skill Gap
              │
              └─────────────┐
                            ↓
                        动态推荐
```

Agent 位于整个闭环之上：

```text
                 HR Agent
                    │
       ┌────────────┼────────────┐
       ↓            ↓            ↓
    HR Tools       RAG        Knowledge Graph
       ↓            ↓            ↓
 PostgreSQL      pgvector      Neo4j
```

# 所以整个项目可以浓缩成 8 个核心业务模块

你后面写论文、做 PPT、做 README、面试介绍，都可以直接使用这套结构：

```text
① HR业务调研与真实数据建设

② 统一岗位—技能体系构建

③ HR培训知识图谱

④ 员工技能画像与Skill Gap分析

⑤ 个性化培训课程推荐

⑥ 自适应Learning Path生成

⑦ 企业知识RAG + HR Training Agent

⑧ 培训反馈、效果评估与动态优化
```

这八块就是**整个项目真正的大纲**。

而你的系统卖点也就非常清楚了：

> **不是做一个“会聊天的 HR Bot”，而是构建一个围绕“岗位能力差距 → 培训推荐 → 学习路径 → Agent辅助学习 → 培训反馈”的企业员工能力发展平台。**

这个定位其实比单独做 RAG 或 Agent Demo 有价值很多。
